# Cataclysm 0.2 — AI Council contract

This is an implementation roadmap for a **real, evidence-bearing development council**, not a roleplay transcript or autonomous deployment claim.

## Scope
Keep Cataclysm as the single evolving game. Each iteration proposes **mechanics** (e.g. enemy archetypes, player choices, wave patterns, cat abilities, environments), not merely parameter changes. Preserve the current playable 0.1 as a rollback point.

## Council and artifacts
1. **Researcher:** read the existing code, issue history, previous proposals, recorded gameplay event reports and available analytics; output citations to file/commit/timestamp. External trend research must identify sources and dates.
2. **Designer:** propose 2-3 distinct mechanics with expected player impact, interactions, controls, and clear acceptance criteria.
3. **Engineer:** estimate scope, risks, interfaces and implementability; reject incompatible mechanics. Output an implementation plan.
4. **Critic / Accessibility:** independently challenge difficulty, mobile touch UX, clarity, performance and unintended incentives. Never fabricate playtest results.
5. **Implementer:** create a temporary feature branch, modify allowlisted game code, add tests and document changes.
6. **QA:** run automated tests and browser-based smoke tests, collect screenshots/logs, compare with baseline and mark untested claims as unknown.
7. **Producer:** synthesize evidence, decide whether to request another iteration or open a draft PR; prepare an educational changelog and suggested video script tied to actual evidence.

Each agent emits a typed JSON artifact with: run_id, role, source_refs, proposal_ids, claims, evidence, uncertainty, objections, decision and output files. All work is append-only and reproducible where possible. Models are not allowed to declare tests passed; only test runner evidence can.

## Orchestration
- Trigger: manual "Cataclysm 0.2" run, later scheduled/feedback-driven runs.
- State machine: intake → research → design → challenge → plan → implement → test → review → draft_pr.
- Gate changes: no secrets exposed to model, restricted workspace, no arbitrary shell commands generated by untrusted agents without policy review, budget limits, maximum iterations and timeouts.
- No direct merge to main; no live deploy or public YouTube release without separate configured approval.
- Failure: save partial artifacts, stop, report actionable reason and permit retry without duplicate branches/videos.

## First Cataclysm 0.2 brief
**Goal:** Make the cat-versus-zombies survival loop more strategic and fun on a phone while retaining one-handed controls and 60-second recording suitability.
Candidate mechanics to evaluate (not preapproved): a short dash with cooldown; two zombie behaviors (chaser and slow tank); fish choices that trade health versus temporary ability; readable wave warnings. The council must choose a small compatible subset using evidence, not implement everything.

## Definition of done
The council autonomously proposes a meaningful new mechanic, changes actual Cataclysm game code, runs real tests, produces a playable preview and a draft PR with verifiable evidence. Human playtest and final deployment remain explicit gates.
