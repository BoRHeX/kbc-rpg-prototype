## 10-pass engineering/preservation and cost contract
Each pass is a new Ubuntu GitHub Actions job. No two Codex invocations in a single job (prevents drop-sudo failure). All assets/source passed via verified GitHub Actions artifacts. Always upload surviving pass content **even if Codex or QA fails**; never delete prior pass output. Each active version artifact is self-contained; after Pass04 freeze 1.7, after Pass07 freeze 1.8, after Pass10 freeze 1.9. One publisher gathers each frozen snapshot, writes honest candidate pages at `docs/cataclysm-1-7-candidate/`, `...1-8-candidate/`, `...1-9-candidate/`, merges one protected PR and attempts single Pages deployment. If artifact absent/failed, use direct predecessor source and an explicit BROKEN/no-evidence label rather than inventing success. Do not overwrite versions 1.0 through 1.69 or other projects.
Art passes must use real OpenAI Image Generation API credentials and caps (up to three PNGs for each of Pass03/05/08, **maximum nine image calls total**). Actual original raster, derived animation frames, original sound/music WAV files and source hashes, not code-drawn placeholder claims. If API fails, art is marked ART-BLOCKED; code work still proceeds.
QA and release are distinct: preserve bad builds, log errors, **do not falsely promote to stable** or imply actual physical Samsung test. Playable browser gate is minimum mobile orientation Chrome startup/canvas rendering only; full campaign/phone requires creator validation. If repository permissions or GitHub Pages fail, preserve Artifacts and PR branch and report honestly.
The owner authorizes **one finite 10-pass run** plus publisher, not unbounded repair loops and not a scheduled 2.0 launch. The studio cannot claim 2.0-ready merely because numbered versions were generated. Use documented real feature evidence in code and test artifacts. Deliver real URLs only after publication succeeds.
