## Goal / world topology
1. The 2400×2400 arena must be a true **continuous torus**: go east long enough and return to the same position from west; north wraps south; all 4 seams connect. No artificial edge warnings, teleport flashes, camera jumps, dead zones, invisible walls or one-way seams. Relative vectors use SHORTEST periodic delta everywhere (AI chase, aim, projectiles, fish, boss, pets, radar/visibility, hazards, collision and damage). Canonical positions always [0, WORLD_SIZE). Implement and use `const WORLD_SIZE = 2400`, `wrapCoord(value)`, `wrappedDelta(from,to)`, and `dist(x,y,x2,y2)` (distance MUST use wrapped deltas). Make navigation visually seamless with repeated art/actors/tiles across the seams (tile offsets ±2400, cull to viewport; camera centered on player). The world is a looping fixed map, not procedurally endless/unbounded storage.
2. **Solid terrain and mutual actor collision.** Player, each zombie type/boss/elite and each permanent companion have real collision circles, cannot go through visible solid terrain or occupy the same space. Buildings and clearly marked large solid objects must block passage. Use stable circle-vs-axis-aligned-rectangle resolution (including periodic seam copies), substep/swept moves (no tunneling during high-speed movement or dashes), wall sliding (not jarring stop), and bounded pair separation. Avoid O(n²) needless cost where possible; max enemies ~72, use broadphase or distance early-outs. Enemy separation must not disable contact damage, attack range or enemy movement. Boss cannot push player into a wall. Character motion and companion formation should remain responsive; no wedging. Honor distinct radii for hero, followers, little zombies and boss.
3. **Open terrain.** Rework procedural world layout to **mostly navigable streets, plazas and clear movement corridors** with sparse, visually clear solid buildings/obstacles; never create narrow corridors or traps. Avoid blocks near seam boundaries and ensure crossing routes are unblocked. Choose conservative solid placement/clearance and preserve open traversal between regions. Building art and actual collision rectangles must ALIGN in world coordinates, not visual facades that appear passable/solid differently. Decoration such as road paint, windows, street light glow and small rubble may remain non-solid. Under no circumstance turn the map into a maze.
4. **Collision for interactive objects.** Bullets must either hit/block on solid terrain (if intended as physical projectiles) or be unmistakably distinguished as ethereal; default to stopping bullets at solid buildings, with an explicit test. Fish, crates/cans, rune pickups, spawn locations (player/enemies/boss/companions), elite events, falling crane targets and powerups must be placed in accessible, non-solid space; never bury rewards in building geometry. Adjust placement via nearest-safe-space search if needed, not by deleting earned items. All world systems must function across seams.
5. **Gameplay compatibility.** Keep 0.9 enemies, actor hit/damage, Health/XP, stamina, powerups, spawning budget, drop rates, companion abilities/squad buffs, rage visuals, terrain effects, rune shields, director, city encounters, 5-minute boss, RNG gameplay progression and scene audio; do not invent new game mechanics beyond toroidal movement/collision. Reevaluate the obsolete edge-escape ability: remove its edge warning/arrow and replace with nothing or reframe it as a non-edge emergency escape only if necessary; no permanent empty HUD. The map has no edges now. Any removed safety buff should not strand the player. Respect 0.9 build metadata and boot handshake.
6. **Mobile graphics and performance.** Continue existing fun illustrated cat graphics and supply crates. Render repeatable city background and actors at seam offsets with VIEWPORT CULLING, avoiding 9 full 2400×2400 canvas redraws. Keep HUD/controls on one landscape screen. Tick performance bounded at max mobs; no excessive allocations, no NaNs; support restart, pause, upgrade overlay, rotate screen. Use deterministic coordinate hashes for decoration; never consume gameplay RNG for visual-only effects.

## Stable testable implementation contracts
These identifiers MUST exist in `docs/preview/game.js` and be used by the simulation:
- `WORLD_SIZE` numeric 2400, `wrapCoord(value)` canonical modulo, `wrappedDelta(from,to)` shortest signed displacement; `dist(...)` toroidal distance.
- `isTerrainClear(x,y,r)`: boolean, returns true iff given character-sized circle does not collide with solid terrain; handles seam.
- `moveWithCollision(actor, dx, dy)`: modifies actor canonical coordinates while sliding against terrain and refusing to tunnel.
- `resolveActorCollisions()`: applies pair separation using the periodic metric for player/enemies/companions, preventing overlaps with terrain, called by game tick every simulation frame.
- The existing `city` array must represent the actually solid buildings used in visible rendering and terrain collision; optional other solidTerrain is allowed, but `city` entries must be real collidable rectangles. No need to expose mutable public debug API.
