# BoRHeZ Cataclysm 1.0 — creative studio pass 1: Make the cats alive

**Creator's executive order, 13 November 2026.** This is a finishing-polish run for the already deployed Cataclysm 1.0, **NOT** a new game, remake, gameplay campaign, or level-100 stress-test project. Read the existing actual game and its companion behavior. Work only in `docs/cataclysm-1-0-major/**` and `docs/cataclysm-100-lab/**`. Retain parity where mechanics are shared, but keep the normal campaign starting Night 1, level 1, and the lab's dedicated test mode. Version remains 1.0. Preserve art, score, boss logic, 100-night progression, permanent companions, mobile smoothness, audio, upgrades, maps, and existing game mechanics.

**Creative freedom is the point.** The studio (writer, gameplay designer, companion-AI engineer, technical artist, QA) invents the cats' individual voices, jokes, running gags, dialogue exchanges, spontaneous reactions and occasional absurd remarks. Do not simply use or paraphrase the creator's few example lines. Make a large, varied, organized LOCAL dialogue library (no live API calls during gameplay), enough genuine variety across the main cat and all eight companion roles that early play does not repeat the same sentences. Contextual one-liners should be short enough to read at mobile speeds. Distinguish a healer's temperament from a sniper's, tank's, bard's, etc. Allow playful conversations and callbacks, as well as increasingly serious behavior around Nights 98–100. A memorable sense of team personality is more important than sheer line count.

**Actual on-character speech:** small readable comic speech bubbles over the speaking cat's head, tracking its real world/screen location rather than a detached subtitle spam ticker. Dialogue is triggered by actual game signals: start and early tutorial moment, injury, a heal (requested/completed), feral/adrenaline activation, missing shots, elite/boss emergence or defeat, squad recruitment, fish hunger/retrieval/eating, waiting, unusual nearby encounters, late-night foreshadowing, victory/death, and incidental banter. Schedule utterances with priorities, speaker cooldown, repetition suppression, camera/HUD collision handling, readable lifetime and a global cap so gameplay is never obscured. Pause/upgrades freeze timers and chatter. NPCs never claim events that did not happen; logic stays deterministic/testable.

**The core companion behavior improvement:** companions occasionally seek real existing fish when safe and on cooldown; collect/feed without stealing or losing the player's earned fish/XP, then return naturally. Respect hazards, visible enemies, distance to hero, healing preparations and role-specific actions. Never let all four disappear into a fishing trip. Give them short feeding comments and interpersonal reactions. After feeding or a reasonable timeout, the squad can adapt/reshuffle formation with meaningful roles and spacing instead of requiring the tactic button. If there are no fish, or the player is threatened, they keep fighting; no starvation or time-based penalty. Auto-activate specials based on real tactical value (targets in range, wounded hero stationary for healer, pressure for tank, useful aim for sniper, etc); avoid wasting cooldowns during empty inter-wave intervals, especially before known boss arrivals. Do not introduce new mandatory player buttons. Main-cat-only solo builds must still work.

**Guide awareness:** the hero should occasionally indicate that the in-game Guide exists in the pause menu, with a brief, self-authored quip and a readable pointing cue if the existing sprite/pose system permits. Stage 2 builds the actual Guide UI; prepare a robust integration contract rather than inventing a second guide.

**Execution:** design, implement, wire into the actual canvas gameplay and companion state machine, and perform local source-level checks. Do not stop at writing samples or a design document. Only edit the two Cataclysm 1.0 game directories; tooling, tests, releases and external projects are maintained by the trusted pipeline. Do not spawn AI calls at runtime or modify protected source art. Prefer reuse of proven animation and character anchors. Leave the optional silly-leg issue alone unless the fix is genuinely safe. Keep browser snapshots functioning and exposing truthful state. The next pass will polish cards and input/menu UI using this exact candidate.
